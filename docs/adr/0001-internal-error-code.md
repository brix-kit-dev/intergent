# ADR-0001 增加错误码 `internal_error`

> **状态**: 已批准，项目负责人 2026-11-07
> **日期**: 2026-11-07
> **改动范围**: 蓝图 6.10、契约的 `ErrorCode`。REST 约定是单向门，所以按蓝图 17.3 走 ADR

## 原因

蓝图 6.2 要求错误都是 `application/problem+json`，带稳定的 `code`，契约里 `code` 是必填项。但 6.10 的错误码表有两个缺口：

- **没有“引擎自己出错”这一项。** 程序缺陷或数据库不可用时，请求只能失败，却没有码可用。
- **`invalid_request` 只写了 HTTP 400。** 请求方法不对、媒体类型不支持、请求体过大，HTTP 都有专门的状态码，比如 405 还要带 `Allow`。

## 决定

| `code` | HTTP | 含义 |
| --- | --- | --- |
| `internal_error`（新增） | 500 | 引擎内部出错，和请求内容无关。响应不含内部细节，凭 `Request-Id` 查日志 |
| `invalid_request`（修改） | 400、405、406、413、415 | 请求格式不对。客户端看 `code`，HTTP 状态保持协议上的含义 |

## 考虑过的其他做法

| 做法 | 为什么不选 |
| --- | --- |
| 500 时用 `model_unavailable` | 它的含义是所有候选模型都失败，会误导调用方。6.10 也规定 `code` 发布后不改含义 |
| 500 时不带 `code` | 违反契约。SDK 按必填字段解析时会出错 |
| 协议错误全部返回 400 | 丢掉 HTTP 语义，通用客户端和代理都靠这些状态码判断 |

## 影响

- 蓝图 6.10 加一行、改一行，版本升到 v1.1，打标签 `blueprint-v1.1`。
- 契约 `ErrorCode` 加一个值。按 6.2 的兼容规则，新增枚举值不算破坏性变更。
- 架构守卫里的错误码名单同步。

## 迁移

不需要。契约还没有发布，没有存量客户端。
