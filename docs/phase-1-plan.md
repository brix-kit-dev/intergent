# 第一阶段开发计划

> **状态**: 草案。第 5 节的事项定下来后改为生效
> **日期**: 2026-11-06
> **依据**: [架构蓝图 v1.0](ai-engine-architecture-blueprint.md) 的 15.1（范围）和第 16 节（红线）

蓝图 0.3 写着实施排期在平台方案第 11 节，但平台方案不在本仓库。它到位之前，第一阶段按本计划执行。本计划只定顺序和验收，不改蓝图：范围和架构的变更仍按蓝图 17.3 走。

## 1. 目标

第一阶段就是蓝图说的 Dev 阶段：部署一个单元 `jp-general`，支撑 AI 客服问答。

做到下面三件事，第一阶段才算完成：

- AI 客服在真实站点上实测通过。
- 单元能部署，备份能恢复。
- 第 16 节的每条红线都有检查在运行。

## 2. 里程碑

按顺序做，前一个收尾后再开始下一个。

| 里程碑 | 做完能看到什么 | 状态 |
| --- | --- | --- |
| M0 工程地基 | 构建、红线检查、CI、第一份契约都能运行 | 完成 |
| M1 租户和身份 | 能开通租户、用密钥换令牌，跨租户读不到数据 | 未开始 |
| M2 最小对话 | 用模拟模型流式回答，断线能续传，能取消 | 未开始 |
| M3 真实模型和信任 | 真实模型回答，超预算或超等级被拒绝，审计可查 | 未开始 |
| M4 知识 | 推送文档后，回答带引用 | 未开始 |
| M5 宿主集成 | 回答时能查宿主数据，Webhook 能送达，能按用户导出和删除 | 未开始 |
| M6 接入和实测 | AI 客服在真实站点上运行 | 未开始 |
| M7 上线准备 | 恢复演练通过，第一版发布 | 未开始 |

## 3. 各里程碑

“红线”一栏是这个里程碑要让检查真正运行起来的红线。“口子”是蓝图 15.1 要求现在就留好的字段或结构。

### M0 工程地基

| 项目 | 内容 |
| --- | --- |
| 范围 | Maven 骨架、架构守卫、CI 和依赖规则、第一份 OpenAPI 契约 |
| 验收 | `engine/verify.sh` 和 GitHub Actions 都通过 |
| 红线 | A-1、A-2、A-7、A-11、A-13、A-17。A-4、A-8、A-15、A-18、S-8、S-9、S-10、T-5 完成一部分，后面的里程碑补齐 |

### M1 租户和身份

| 项目 | 内容 |
| --- | --- |
| 范围 | 租户底座：PostgreSQL、迁移、行级安全、跨租户测试、适配器 `store-postgres`、`migrate` 角色 |
| | 接口层约定：错误格式、`Request-Id`、追踪、版本头、幂等 |
| | 身份：API 密钥、短期令牌、匿名令牌 |
| | `admin` 角色：开通租户、应用和第一把密钥 |
| | 文本扫描和迁移检查管的红线 |
| 验收 | 用 `admin` 开通租户；用密钥换短期令牌；一个租户读不到另一个租户的数据，没有租户上下文时什么都读不到；错误都是 `application/problem+json` |
| 红线 | A-3、A-4、A-5、A-6、A-8、S-10、T-1、T-2、T-5 |
| 口子 | `parent_tenant_id`、`On-Behalf-Of`、密钥里的单元码 |

### M2 最小对话

| 项目 | 内容 |
| --- | --- |
| 范围 | 网关骨架和模拟模型 |
| | `conversation` 模块：会话、消息、事件日志、流式回答、续传、取消、幂等重试、心跳 |
| 验收 | 模拟模型流式回答；断线后续传不重不漏；取消有效；同一个键重试不重新生成；生成方崩溃后读取方写入 `error` 事件 |
| 红线 | A-14、A-16 |
| 口子 | 流式事件类型齐全，契约里已有 |

### M3 真实模型和信任

| 项目 | 内容 |
| --- | --- |
| 范围 | 先做验证 V-4，再做三个模型适配器：Anthropic、Google、OpenAI 兼容 |
| | 网关：模型注册表、路由、备用、重试、提示词管理、区域包 `regions/jp` |
| | `metering`：用量、预算、`GET /v1/usage` |
| | `trust`：地区门禁、数据等级、基础检查、审计 |
| | 可观测：追踪、指标、日志脱敏 |
| | 评测：CI 里跑黄金集 |
| 验收 | 真实模型流式回答；主模型失败时换备用；预算用完返回 `budget_exceeded`；内容等级超限返回 `no_eligible_model`；输入和输出检查生效；审计可查；提示词改坏时评测阻止合并 |
| 红线 | A-9、A-12、A-15、S-1、S-6、T-3、T-4、R-2、R-4 |
| 口子 | 注册表里的合同属性、所有检查都是端口、灰度字段、区域包结构 |
| 需要提供 | 模型账号和开发专用密钥，带消费上限；黄金集的考题来源；是否用 Langfuse 云服务 |

### M5 宿主集成

| 项目 | 内容 |
| --- | --- |

## 6. 怎么执行

- 每个里程碑开工前拆成小点，列出顺序。里程碑内的顺序可以调整。
- 一次只做一个小点，做完才开始下一个。做完指代码和测试、端到端验证、文档、合并都完成。
- 过程中发现的新问题放到点列表末尾，不扩大当前小点。
- 里程碑收尾时演示验收内容，再更新本文件的状态。
- 调整里程碑的顺序或内容时改本文件。改范围、红线或单向门时按蓝图 17.3 走。
